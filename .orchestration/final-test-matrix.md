## Scope and interpretation

Scope: Discover, Maps, Community and Chat, plus Profile, auth/onboarding, booking, coach tools and the admin console. Courts and Shop are excluded. No payment-processor requirement is assessed: BOOK'D takes no payment. Booking prices, displayed purchase/redemption amounts and server-recorded `total_cents` are assessed.

Each row follows a concrete control, state, role, data condition or failure branch. **WORKS is a static finding, not a claim of an executed mobile or production test.** A working navigation or filter control does not clear a separately identified downstream defect. The actual-behavior column states that boundary. Repeated roles and entry points are counted as scenarios, not distinct root causes.

- **WORKS:** the bounded behavior is correctly wired by source, including a deliberately handled rejection or explicit empty state.
- **BROKEN:** the source demonstrates a defect under the row’s stated preconditions; the defect column identifies the cause and location. For database-dependent findings, this means the checked-in SQL/grants/migrations; whether the live project matches them remains unverified.
- **UNVERIFIABLE-WITHOUT-DATA:** the path is traced, but completing it requires live identities/rows, deployed functions/policies, provider configuration, a device, or a runtime condition that could not be exercised. This label also covers device/provider prerequisites despite its fixed name.
- **NOT-REACHABLE:** there is no normal first-release UI path to the scenario. A retained router case, component or SQL function alone does not make it reachable.

Source references are clickable absolute local links labelled with project-relative `file:line`. Entry-point citations identify the control/branch, including the nearest related screen for absent controls. Supporting citations identify the implementation actually executed.
